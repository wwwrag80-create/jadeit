# دمج محرك المزامنة في برنامج العملاء (rageh.exe)

العميل **لن يرى أي تغيير** في الواجهة — لا زر ولا شاشة. كل ما يُضاف خيط خلفي صامت ومؤشر صغير اختياري.

---

## الخطوة ١ — انسخ الملف

ضع `cloud_sync.py` بجوار `rageh-1-34-14.py` في نفس المجلد.

## الخطوة ٢ — ضع مفاتيح Supabase

افتح `cloud_sync.py` وعدّل السطرين في الأعلى:

```python
SUPABASE_URL = "https://xxxxx.supabase.co"
SUPABASE_ANON_KEY = "eyJhbGci..."      # مفتاح anon فقط — لا تضع service_role أبداً
```

> مفتاح `anon` آمن هنا لأن سياسات السحابة تمنعه من قراءة أي جدول؛
> كل ما يستطيعه هو استدعاء دوال المزامنة، وكل دالة تتحقق من رمز العميل السرّي أولاً.

## الخطوة ٣ — أضف ٣ أسطر للبرنامج

### أ) الاستيراد (أعلى الملف مع باقي الاستيرادات)

```python
from cloud_sync import CloudSync
```

### ب) التشغيل — داخل `__init__` بعد `self.init_database()` مباشرة

```python
        # ====== محرك المزامنة السحابية (خيط خلفي صامت لا يمس الواجهة) ======
        self.cloud_sync = CloudSync(
            db_path=self.db_path,
            session_file=DEVICE_SESSION_FILE,
            app_version="1.34.14",
            on_status=self._on_sync_status,
        )
        self.cloud_sync.start()
```

### ج) مؤشر الحالة (اختياري لكنه مفيد) — أضف هذه الدالة داخل الكلاس

```python
    def _on_sync_status(self, text):
        """يُستدعى من الخيط الخلفي — نمرّره لخيط الواجهة عبر after حتى لا يسقط Tkinter"""
        try:
            self.after(0, lambda: self.lbl_cloud_sync.configure(text=text))
        except Exception:
            pass
```

### د) الإيقاف عند الإغلاق — داخل `on_app_closing`

```python
        try:
            self.cloud_sync.stop()
        except Exception:
            pass
```

### هـ) رفع فوري بعد العمليات المهمة (اختياري)

في نهاية `recalculate_all()` أو بعد ترحيل فاتورة:

```python
        if hasattr(self, 'cloud_sync'):
            self.cloud_sync.sync_now()
```

بدونه ترتفع الحركات خلال ١٠ ثواني على أي حال.

## الخطوة ٤ — اربط جهاز كل عميل

من Supabase شغّل هذا لتأخذ بيانات الربط:

```sql
select business_name, id as tenant_id, sync_token from public.tenants order by business_name;
```

ثم على جهاز العميل، افتح الملف:

```
%LOCALAPPDATA%\JadeiteERP\device_session.json
```

وأضف فيه السطرين (مع الإبقاء على ما بداخله):

```json
{
  "tenant_id": "المعرّف من الاستعلام",
  "sync_token": "الرمز من الاستعلام"
}
```

> الجهاز بلا هذين المفتاحين يعمل **محلياً بشكل طبيعي تماماً** وتتوقف المزامنة بهدوء — لا رسائل خطأ ولا تعطّل.

## الخطوة ٥ — البناء

```
pyinstaller --onefile --noconsole --add-data "cloud_sync.py;." rageh-1-34-14.py
```

لا تحتاج أي حزمة جديدة: المحرك يستخدم `urllib` و`sqlite3` و`threading` من المكتبة القياسية فقط.

## ماذا يفعل المحرك بالضبط

| الحالة | السلوك |
|---|---|
| أول تشغيل | يضيف جدول `sync_outbox` ومحفّزات على `invoices`، ويُدرج **كل** التاريخ القديم للرفع |
| إضافة/تعديل/حذف حركة | المحفّز يسجّلها تلقائياً — **بدون تعديل أي سطر في كود البرنامج** |
| كل ١٠ ثواني | يرفع دفعة (٢٠٠ حركة) إن وُجد جديد |
| انقطاع الإنترنت | يبقى كل شيء في الصندوق، ويتراجع تدريجياً (٥ ثواني ← ٥ دقائق) ثم يعيد المحاولة |
| عودة الإنترنت | يرفع كل المتراكم تلقائياً بالترتيب |
| انقطاع بعد الكتابة وقبل الرد | إعادة الرفع لا تُنشئ تكراراً — المفتاح `(tenant_id, seq_no)` |
| كل دقيقة | نبضة حضور تُظهر للمدير: متصل الآن، عدد المعلّق، إصدار البرنامج، آخر خطأ |
| رمز مزامنة خاطئ | تتوقف المزامنة بهدوء ويظهر سبب واضح — والبرنامج يعمل محلياً كالمعتاد |

## نقطة مهمة عن اتجاه المزامنة

المزامنة **باتجاه واحد**: من جهاز العميل ← إلى السحابة.

هذا مقصود ويطابق ما طلبته: العميل مصدر الحقيقة، ولوحة المدير للمشاهدة والمتابعة.
لو أردنا لاحقاً أن يعدّل المدير بيانات عميل من الويب فسنحتاج طبقة حل تعارضات
(أي التعديلين يفوز عند تعديل نفس السطر في الجهتين) — وهي قابلة للإضافة لكنها
قرار محاسبي يحتاج نقاشاً، فلم أضفها من طرفي.

## للتحقق أن المزامنة تعمل

```sql
-- عدد الحركات الواصلة من كل عميل
select t.business_name, count(x.id) as حركات, max(x.synced_at) as آخر_وصول
  from public.tenants t
  left join public.transactions x on x.tenant_id = t.id
 group by t.business_name order by 1;

-- حالة الأجهزة
select * from public.tenant_devices order by last_sync_at desc;
```
