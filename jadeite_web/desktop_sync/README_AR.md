# تحديث برنامج العملاء — المعمارية الهجينة

## الملفات

| الملف | الوظيفة |
|---|---|
| `rageh-1-34-14-cloud.py` | **نسخة المدير** (مصدر الكود — فيها لوحة المدير) |
| `rageh-CLIENT.py` | **نسخة العميل** — تُولَّد آلياً بـ `python make_client_build.py`، ولا تُعدَّل يدوياً |
| `make_client_build.py` | يولّد نسخة العميل: يزيل المفتاح السري ولوحة المدير |
| `cloud_sync.py` | محرك الرفع الخلفي الصامت |
| `sync_down.py` | سحب بيانات المصنع من السحابة عند الدخول |
| `supabase_api.py` | عميل Supabase بدون حزم خارجية (للاستخدام المستقل) |
| `login_screen.py` | شاشة دخول مستقلة (لمشروع جديد يعتمد Supabase Auth) |
| `patch_client_app.py` | السكربت الذي ولّد النسخة المعدّلة (لإعادة التطبيق على نسخ أحدث) |

## ما تغيّر في نسخة العميل

1. **أُلغي `device_session.json` نهائياً** — لا يوجد أي سر على القرص.
   رمز المزامنة يصل مع استجابة تسجيل الدخول ويبقى في الذاكرة فقط.
2. **بعد الدخول مباشرة:** شاشة «تجهيز بيانات المصنع» ترفع ما لم يُرفع بعد
   ثم تسحب نسخة السحابة وتدمجها محلياً، ثم يفتح النظام.
3. **أثناء العمل:** خيط خلفي يرفع كل حركة جديدة خلال ١٠ ثواني.

## التشغيل

```bash
python rageh-1-34-14-cloud.py
```

الملفات الثلاثة (`cloud_sync.py`, `sync_down.py`, `supabase_api.py`) يجب أن تكون
في نفس المجلد.

## البناء كملف تنفيذي

```
pyinstaller --onefile --noconsole ^
  --add-data "cloud_sync.py;." ^
  --add-data "sync_down.py;." ^
  --add-data "supabase_api.py;." ^
  rageh-1-34-14-cloud.py
```

> ⚠️ **المفتاح السري لم يعد مكتوباً داخل الكود إطلاقاً.** نسخة المدير تقرأه عند
> التشغيل من أحد مكانين:
>
> 1. متغيّر البيئة `JADEITE_SUPABASE_SECRET_KEY`، أو
> 2. ملف نصي اسمه `admin_secret.key` بجانب البرنامج (سطر واحد فيه المفتاح).
>
> الملف `admin_secret.key` مستبعد من git في `.gitignore` — **لا ترفعه ولا ترسله لأحد**.
> ونسخة العميل (`rageh-CLIENT.py`) لا تحاول قراءته أصلاً.
>
> كلمة مرور لوحة المدير المحلية تُغيَّر بمتغيّر البيئة `JADEITE_ADMIN_PASSWORD`
> (الافتراضية `admin` معروفة لكل من يقرأ الكود).
>
> **بناء نسخة العميل:** `python make_client_build.py` ثم ابنِ exe من `rageh-CLIENT.py`.
> **قبل أي تسليم:** `python run_all_checks.py rageh-CLIENT.py` — يفشل لو وُجد أي مفتاح سري في الكود.

## سلوك النظام في الحالات المختلفة

| الحالة | ماذا يحدث |
|---|---|
| دخول أول مرة على جهاز جديد | تُسحب كل بيانات المصنع من السحابة قبل فتح النظام |
| انقطاع الإنترنت أثناء العمل | البرنامج يعمل طبيعياً، والحركات تتراكم وتُرفع عند عودة الاتصال |
| العميل عمل أسبوعاً بلا إنترنت | عند الدخول يُرفع المتراكم **أولاً** ثم يُسحب المدموج — لا يضيع شيء |
| فشل السحب من السحابة | تنبيه واضح، ويفتح النظام بالبيانات المحلية ويعيد المحاولة لاحقاً |
| جهازان لنفس المصنع | كلاهما يرفع، والدمج بمفتاح رقم الفاتورة — لكن جهازاً واحداً فعّالاً فقط (راجع HOW_IT_WORKS_AR.md) |
| تعديل المدير من لوحة الويب | يغيّر نسخة السحابة فقط — **لا ينزل لجهاز العميل** (المزامنة باتجاه واحد منذ RECOVERY_AR.md) |
