# جاديت ERP — برنامج سطح المكتب + السحابة (Supabase)

نظام إدارة مصانع الذهب: **برنامج سطح مكتب** (Python + CustomTkinter + SQLite) عند كل عميل،
و**برنامج المدير** الذي يفتح بيانات أي عميل كما هي على جهازه، عبر **Supabase**.

> 📋 **تقرير المراجعة الشاملة وكل الدفعات: [`REVIEW_AR.md`](REVIEW_AR.md)** — ابدأ منه.

> **الدفعة ٢١:** أُزيل تطبيق الويب ورفع الحركات صفاً صفاً. السحابة تحمل لكل عميل **نسخته الكاملة
> فقط** (مضغوطة وخفيفة)، وبرنامج المدير يقرؤها مرآةً حرفية.

## ٢) كيف تعمل البيانات

| المكان | ماذا فيه |
|---|---|
| **جهاز العميل** | قاعدة SQLite — مصدر الحقيقة. يعمل بلا إنترنت تماماً |
| **السحابة** | لكل عميل **نسخة كاملة واحدة** من قاعدته (`db_backups`): بلا فهارس ومضغوطة بـ xz، تُرفع عند تغيّر البيانات فقط — ومعها حسابات الدخول ورموز المزامنة |
| **برنامج المدير** | ينزّل نسخة العميل الكاملة ويعرضها كما هي حرفياً، ويتحدّث تلقائياً عند وصول نسخة أحدث — ولا يرفع شيئاً أبداً |

## ٣) قاعدة البيانات — في Supabase → SQL Editor

| # | الملف | متى |
|---|---|---|
| ١ | `00_repair_auth.sql` | عند ظهور خطأ 500 `Database error querying schema` |
| ٢ | `INSTALL_ALL.sql` | التثبيت — يجمع المخطط والصلاحيات والدوال بالترتيب |
| ٣ | `01_create_admin.sql` | بعد إنشاء المستخدم في Authentication |
| ٤ | `18_storage_diet.sql` | تنظيف أسبوعي تلقائي وتقرير المساحة (ضمن INSTALL_ALL أيضاً) |
| ٥ | `19_remove_web.sql` | **مرة واحدة**: يحذف حركات الويب ويمنع رفعها من جديد |
| ٦ | `20_admin_download.sql` | برنامج المدير يفتح نسخة العميل عند دخوله باسم العميل (بلا مفتاح المدير)، وفي آخره **تقرير**: لكل عميل هل وصلت نسخته ومتى (ضمن INSTALL_ALL أيضاً) |
| ٧ | `21_access_control.sql` | **مدة الاشتراك وعدد الأجهزة** لكل مصنع (من لوحة المدير ← «⚙️ الاشتراك والأجهزة»)، وجدول العملاء للمدير وحده. في آخره **تقرير** الاشتراكات والأجهزة (ضمن INSTALL_ALL أيضاً) — شغّله **مع** تحديث البرامج إلى 1.68.0 |
| ٨ | `23_cloud_accounts_only.sql` | **مرة واحدة بعد التحديث إلى 1.95.0**: السحابة للحسابات والصلاحيات وحدها — يحذف النسخ الكاملة المخزّنة (`db_backups`) ويمنع امتلاءها من برنامجٍ قديم، ويحذف جدول روابط 1.94 (الرابط صار ثابتاً بلا سحابة). البيانات كلها على أجهزة المصانع — خذ نسخة من «الرابط المباشر» ← ⚙️ لوحة التحكم قبل تشغيله |
| ٩ | `24_live_admin_link.sql` | **رابط المدير في برنامج المدير وحده** (1.96): بصمة مفتاح الرابط لكل حساب، وعنوان جهاز المصنع في وسيط الرابط — لا بيانات ولا الرابط نفسه (ضمن INSTALL_ALL أيضاً) — شغّله **مع** تحديث البرامج إلى 1.96.0 — و**أعِد تشغيله مرة** مع 1.96.1 (يضيف «حال الرابط» التي يراها المدير في «🩺 فحص») |
| ١٠ | `25_password_hardening.sql` | **كلمات مرور الحسابات bcrypt** (1.97): تُحوَّل البصمات الموجودة في مكانها، وكل كلمة مرور جديدة عند حفظها، والدخول كما هو — شغّله **مرة** مع تحديث البرامج إلى 1.97.0 (ضمن INSTALL_ALL أيضاً) |
| ١١ | `26_sub_admins.sql` | **المدراء المساعدون** (1.98): جدول `sub_admins` ودالة `verify_sub_admin_login` صارا في ملفات النظام — كلمات مرورهم bcrypt (والموجود يُحوَّل في مكانه)، وحدّ محاولات التخمين ١٠ خلال ١٥ دقيقة، والاسم لا يتكرر، والجدول للمدير وحده — شغّله **مرة بعد** `25_password_hardening.sql` (ضمن INSTALL_ALL أيضاً) |

الملفات المرقّمة هي **المصدر**، و`INSTALL_ALL.sql` يُولَّد منها آلياً:

```bash
python3 tools/build_install_all.py
```

## ٤) الفحوص

```bash
cd desktop_sync && python3 run_all_checks.py && python3 run_all_checks.py rageh-CLIENT.py
cd .. && python3 tools/check_sql.py && python3 tools/build_install_all.py --check
bash supabase/tests/run_sql_tests.sh         # على PostgreSQL محلي فقط (PGHOST/PGUSER…)
```

كلها تعمل تلقائياً على GitHub مع كل دفعة (`.github/workflows/ci.yml`).

> ⚠️ لا تضع **service_role key** في نسخة العميل إطلاقاً. مفتاح المدير يوضع في
> `desktop_sync/admin_secret.key` على جهازك فقط (مستبعد من Git).
